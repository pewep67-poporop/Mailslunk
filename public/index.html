      Guide — how to use MailSleuth

      1. Choose Windows or Linux in the dashboard to set the platform for the next run; Auto-detect keeps the value found in the file.
      2. Add .eml, .msg, .mbox, .emlx, .mht, .mhtml or .txt files (single, multiple, or a whole folder). PST/OST must be exported to EML first with readpst or Outlook.
      3. Press Analyze. Three live lines show the file, the stage and the detail; the amplitude bar and the percentage show real progress. Pause stops after the current file, Stop keeps finished results, Cancel discards the run.
      4. Results opens automatically. The first strip identifies the email platform (Outlook, Exchange, Thunderbird, Apple Mail, Gmail, Maildir, mbox).
      5. Every message can be expanded to read the preserved headers and the text/HTML body. Remote content is blocked.
      6. The report carries a SHA-256 digital seal in the bottom-right corner. Verify it any time with “Verify signature”.
      7. URL statistics are grouped by target (sender, body, attachment, imported). Export them to CSV or import CSV/JSON/XML/TXT for one-pass local re-analysis.
      8. The entity graph at the end is built only from evidence (headers, IPs, URLs, hashes); it does not guess identities.
      9. 100% offline forensic: no external API, no reputation feed, no AI/ML verdict. Analysis uses local Python libraries and evidence-backed rules.

      Notes and cautions

      • Không truy DNS live: SPF/DKIM/DMARC đọc từ Authentication-Results trong header hoặc snapshot DNS local. GeoIP dùng MaxMind tại máy.
      • Duplicate Message-ID values are normal in exported mailboxes; the tool keeps every record and its filename/folder provenance.
      • A missing display name is not proof of spoofing; findings show the evidence and the weight used.
      • Administrators must enroll with the offline keygen (password + CCCD salt). The CCCD is never stored.
      • The map is an internal schematic, not an online tile service; it marks the server location found in the mail.
